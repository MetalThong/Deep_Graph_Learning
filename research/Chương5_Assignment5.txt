Abstract
This lecture presents a unified development framework for modern intelligent systems.
The course begins with Deep Learning, which enables systems to learn representations and
predictive functions from data. It then introduces Knowledge Graphs for representing struc-
tured knowledge and relationships, Retrieval Augmented Generation (RAG) for retrieving
external information before language generation, and intelligent agents for combining rea-
soning, memory, tools, retrieval, and action.
The central message is that these technologies are complementary. Deep Learning pro-
vides learned representations and predictive models; Knowledge Graphs provide structured
relationships; RAG provides access to external information; large language models provide
language understanding and generation; and agents coordinate these components to achieve
a goal.
Students progressively implement these ideas using Python, embeddings, vector retrieval,
knowledge graphs, and language models. The final project is an intelligent assistant that
can retrieve information, reason over structured knowledge, use learned models, and perform
useful actions.

1 Introduction
Artificial Intelligence systems have evolved from systems that perform a single prediction into
systems that can combine learning, knowledge, retrieval, reasoning, and action.
A traditional machine learning system may answer a question such as
“Is this image a cat or a dog?”
A more advanced intelligent system should be able to answer
“Why is this image classified as a cat, what related information do we know about
cats, and what should the user do next?”
These are fundamentally different capabilities.
A useful development framework is
Intelligent System= Learning +Knowledge +Retrieval +Reasoning +Action. (1)
In this framework:
• Deep Learning provides learning.
• Knowledge Graphs provide structured knowledge.
• RAG provides information retrieval.
• Large Language Models provide language understanding and generation.
• Agents provide planning, tool use, memory, and action.
The goal of this lecture is to understand how these components can be integrated into one
intelligent system.

4 Why Learned Models Need External Knowledge
Suppose a student builds a neural network for university information.
The model may learn patterns from training data, but it does not automatically know a
newly published university regulation.
This illustrates an important distinction:
Model Parameters̸= Current Knowledge. (11)
A trained model contains information encoded during training. An intelligent system often
needs information that is:
• current,
• private,
• domain-specific,
• stored in documents,
• stored in databases,
• continuously updated.
Therefore, the system should retrieve external information when needed.
This is the basic motivation for RAG.
5 Knowledge Representation
Before introducing Knowledge Graphs, consider the difference between unstructured and struc-
tured information.
A document may contain:
“Artificial Intelligence is offered by the Department of Information Technology. The
course requires Linear Algebra and Programming.”
Humans can easily identify the relationships.
A computer can represent them explicitly as
(Artificial Intelligence,offered_by,Information Technology),
(Artificial Intelligence,requires,Linear Algebra),
(Artificial Intelligence,requires,Programming).
(12)
These are knowledge triples.

9 Graph Databases
For larger systems, graph databases can store entities and relationships explicitly.
One popular graph database is Neo4j.
A graph database allows queries such as
1 MATCH (c:Course)-[:REQUIRES]->(p)

3 RETURN c
The important idea is that the query follows relationships rather than searching only for text
similarity.

14 Why RAG is Important
RAG provides several important advantages.
14.1 Current Information
The knowledge base can be updated without retraining the language model.
14.2 Domain Knowledge
The system can use university documents, company documents, technical manuals, regulations,
research papers, or personal notes.
14.3 Evidence
The system can return the retrieved documents as evidence.
14.4 Reduced Hallucination
RAG does not guarantee correctness, but grounding generation in retrieved evidence can reduce
unsupported answers.

18 GraphRAG

Question→Graph Retrieval→Context→Generation. (26)

1. document loading;
2. text splitting;
3. entity extraction;
4. relationship extraction;
5. graph construction;
6. embedding generation;
7. graph/vector retrieval;
8. context construction;
9. LLM generation.
Modern Neo4j tooling supports knowledge graph construction from PDF/text and several
retrieval approaches including vector, graph-based, hybrid, and Text-to-Cypher retrieval. [1]

24 A Unified Mathematical View
Let
x (31)
denote the user’s input.
A learned model produces a representation
h =fθ(x). (32)
The query is transformed into a retrieval representation
q =fϕ(x). (33)
The retrieval system returns
Dk =R(q,K), (34)
whereK is the external knowledge base.
A Knowledge Graph retrieval operator may be written as
Gk =G(q,G ), (35)
where G is the graph.
The complete context is
C = Combine (Dk,Gk,h ). (36)
The language model then produces
y = LLMθ(x,C ). (37)
For an agent, the process is iterative:
st+1 =F (st,xt,Ct,at), (38)
where
• st is the agent state,
• xt is the current observation,
• Ct is retrieved context,
• at is an action.
